# 按改动选择验证

确认 checkout、分支、工作区状态、目标 remote/ref 和实际基点，检查完整 diff。保护用户未提交内容；不只凭文件列表判断影响，不猜默认分支，不把提交成功当成交付通过。

先发现目标项目已有的检查、hooks 和 CI，再按改动选择能捕获真实回归的最小证据：

- 文档与 Skill：核对命令及引用，运行已有链接、结构和格式检查，检查 `git diff --check`。不为验证示例执行付费或破坏性操作。
- 行为与接口：运行所属测试或可重复的针对性检查；公共契约改变时覆盖受影响的消费者。
- 模型可见内容、CLI 或 UI：检查实际入口和最终输出；相关快照变化按行为变化审阅。
- 清单、导出、构建配置或 worker/bin：验证实际构建产物与启动入口，单测不能证明打包正确。
- 异步、并发和恢复：覆盖受影响的失败、取消与重复执行路径，核对外部状态、资源清理和原件保留。

相关证据已通过且未被后续修改或合并影响时不重复运行。仅在修改跨越多个子系统、定位 CI 失败或用户要求时扩大检查；效果实验遵循独立协议，不作为普通交付的默认步骤。

失败先诊断并在授权范围内修复；缺环境时明确实际命令、失败与未验证范围，不降低门槛或跳过 hook 来冒称通过。报告运行完成、检查通过和远端 CI 状态各自的事实。

用户已授权提交或推送时，只暂存本次文件，审阅暂存区后正常提交与推送，读回远端 SHA。远端并发更新用正常合并处理；确需已授权的历史改写时记录实际远端 OID 并用精确 lease，不能裸用 force。CI 仍在运行就保留 pending，不用空提交反复触发。
