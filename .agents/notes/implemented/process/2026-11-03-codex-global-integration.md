# Agent Note: Codex 全局入口保留仓库单一来源

Status: implemented

六项 Skill 通过用户目录软链接接入，协作习惯通过附加配置中的短引导读取源文件，以便以后新对话使用同一份维护内容；代价是本 checkout 必须保留在稳定可读的位置。安装与维护方法归[全局接入](../../../../docs/codex-global.md)。

此选择部分扩展[通用维护 fork 决定](2026-11-03-general-maintenance-fork.md)：维护者已授权自己的 Codex 全局使用这些内容，其他使用者仍自行选择个人习惯。用户要求保留已有 `AGENTS.md`，因此安装只添加技能软链接及 `developer_instructions` 管理块，继续加载原全局与项目指令；当前请求和项目约束优先。

复制安装会产生需要同步的第二份技能正文及共享引用，难以保证仓库更新生效；软链接保留同一来源。将习惯直接合入全局 `AGENTS.md` 会修改用户要求保留的文件，`AGENTS.override.md` 会遮蔽原文件，替换基础模型指令也超出所需范围。因此使用附加字段，只保存读取路径，不把本仓的根指令应用到其他项目。

安装前预检同名入口、已有附加指令、禁用规则和配置文件形式，存在冲突时保留现状；重复安装及只读检查都有隔离测试。配置管理块之外的原字节保持，失败时移除本次新增链接，不改已有入口。全局工具链、hooks 和模型配置仍由原环境拥有。

五项隔离行为测试验证指令保留、共享引用、源更新、冲突拒绝、重复安装和检查只读。桌面版 Codex 0.166.0-alpha.5.1 与命令行版 0.160.1 的 `debug prompt-input` 验证六项用户级技能路径、习惯读取引导、原全局与项目指令同时进入新会话启动输入，维护仓库根指令未进入其他项目。该验证不调用模型，尚不证明每条偏好在真实任务中的应用效果；后续按实际案例修订。
